# E5-T8 — 訓練監控 UI

## 啟動

```
horos ui <project>          # 專案需有 train 與 valid 兩個非空 split
瀏覽器開 http://localhost:5000/train
```

## 測試步驟

### A. 超參數推導與覆寫（E5-S1, E5-S2）

1. 進入 Training 頁。「Train」面板（文字精簡：資料一行 train / valid / test · labels · classes，細節在滑鼠提示）應顯示：
   - Model 下拉選單只列出可訓練模型（RF-DETR 四個尺寸），旁邊有 Apache-2.0 授權徽章
   - 超參數列表：每一列只有「名稱 / 控件」一行；滑鼠停在名稱上時 tooltip 顯示推導理由
     （例：`635 images: small datasets need more passes to converge`），游標樣式不變、名稱旁沒有任何符號；
     被覆寫的列名稱變藍，tooltip 說明這是 user override 並可用 auto ↺ 還原。
     Run history 的「Hyperparameters used」表同樣改為 hover 顯示理由
   - 預設只展開 epochs / batch_size / resolution / lr 四個常用參數；其餘可調的推導值
     （grad_accum_steps、warmup_epochs、early_stopping 開關、early_stopping_patience、
     early_stopping_use_ema、lr_scheduler、mosaic_ratio、num_workers）、
     「Best checkpoint」與 Seed 收在「Advanced settings」摺疊區，標題列出裡面有哪些；
     點開後狀態會記住（重新整理仍展開）
   - 表單上每一個顯示的超參數都能改：數值用 stepper、布林與 lr_scheduler 用下拉；
     改過的欄位外框變藍並出現「auto ↺」還原。不便手動調整的值
     （aug_config、lr_scheduler_kwargs、augmentation_backend）不顯示，但仍記錄在 run 的 hparams 裡
   - 非 TrainRunConfig 欄位的覆寫（如 early_stopping_patience）透過 `extra` 送出，
     推導結果中同樣標為 user override
2. macOS 上應看到黃色提示 `Suitable for small-dataset pipeline validation only.`
   （由 /api/v1/capabilities 驅動，非前端硬編碼）
3. 修改 epochs 輸入框（例如改成 5）：
   - 輸入框邊框轉藍、理由變成 `user override`、旁邊出現 `auto ↺` 按鈕
   - 其他列的推導值不變（部分覆寫不影響其他推導）
4. 按 `auto ↺`：值回到推導值，理由恢復
5. 切換 Model（如 Nano → Medium）：resolution 與 batch_size 隨模型重新推導
6. 類別不均 >3:1 的資料集會顯示 ⚠ 提示（誠實聲明後端沒有取樣 knob）
7. 類別選擇：取消勾選部分類別
   - 類別列下方的「Training data」統計即時更新：影像數（train / valid / test）、標註數、類別數，
     並註明 `N images with none of the selected classes excluded`
   - 超參數重新推導：依影像數的規則（epochs、增強強度、patience、loader workers）跟著變，
     推導理由的句子引用的是新的影像數；notes 多一條說明排除了幾張背景影像
   - 出現「keep images that contain none of the selected classes as background negatives」勾選框；
     勾起後影像數回到全部，統計改為 `N background-only images kept`，超參數再次重新推導
   - 全部類別勾選時勾選框隱藏，統計不加註
   - 若排除背景後某個 split 沒有影像，按 Start 會得到明確錯誤
     `The selected categories [...] have no annotated images in the valid split …`，並提示三種解法

### B. 開始訓練與即時監控（E5-S3）

7. 按「Train」：
   - 下方出現「Run」面板：RUNNING 狀態徽章、run id、進度條
   - phase 文字顯示 `epoch k/N`，進度條隨 epoch 前進
8. 第一個 validation epoch 結束後：
   - 折線圖出現 loss 曲線（train/loss、val/loss 等，多序列各自配色 + 圖例）
   - 非 loss 指標（mAP 等）以卡片顯示最新值
9. 展開「Hyperparameters used (with reasons)」：
   - 顯示這個 run 實際使用的每個超參數、值、理由；被覆寫的值帶 `override` 徽章

### C. 停止訓練（E5-S4）

10. 訓練中按紅色「Stop」→ 確認對話框 → 確定：
    - 狀態轉為 STOPPED（灰色徽章）
    - 已完成 epoch 的 checkpoint 保留在 `<project>/runs/<run_id>/checkpoints/`

### D. Run 歷史

11. 「Run history」面板列出所有 run（新的在上）：id、模型、狀態、時間、checkpoint 檔名
12. 點任一列可載回該 run 的完整事件與曲線（不輪詢已結束的 run）
13. 重新整理頁面：進行中的 run 自動重新接上並繼續輪詢；無進行中則載入最新一筆

### E. 錯誤路徑

14. 沒有 valid split 的專案按 Start：紅色錯誤訊息
    `Training needs a non-empty train and valid split ...`，不會產生 run
15. 已有 run 在跑時再按 Start：明確拒絕（one training at a time），原 run 不受影響

## 預期結果

不填任何超參數按一個按鈕即可開始訓練；每個推導值都看得到理由；
loss 曲線即時更新；中停保留最佳權重；歷史 run 可回看。

### Resume 後的曲線（2026-09-14）
1. 對已完成／停止的 run 按 Resume 再訓練：新 run 從 checkpoint 的 epoch 接續（例如 29→50），自己的 events 只有 29 之後
2. 開新 run 的頁面：曲線從 epoch 0 畫起——父 run（可多層，`resumed_from` 鏈）的 metrics 以 inherited_events 帶回、
   在接手的 epoch 處截斷；RUN 標題列多「· resumed <父 run id>」，hover 顯示整條鏈
3. 假後端（epoch 從 1 重數）不會重疊：沒有可繼承的點時就只畫自己的

## 已知限制

- 指標僅在 validation epoch 結束時更新（rfdetr 逐 epoch 驗證），batch 級 loss 不串流
- OOM 自動退階（E5-T6b/T6）尚未實作：OOM 會顯示為 failed 並附錯誤訊息
- 續訓（E5-T5）尚無 UI 入口

## 2026-09-13 文字精簡

- 標題與按鈕改為短字：Train / Run / Resume / Export；匹出格式選單只留名稱（PNG、PDF、Excel；PyTorch、ONNX、TensorRT · this GPU、TFLite、TFLite int8），
  說明移到選單與下方一行註記的滑鼠提示
- 資料摘要合併成一行「76 / 13 / 12 · 101 labels · 2 classes」，沒有 test set 時多一個「no test set」小標；Data allocation 段落移除
- Verdict（原 Conclusion & suggestions）每個發現只顯示一行標題，點開才看到細節與建議
- Advanced settings 標題只顯示項目數，內容清單改到滑鼠提示；Hyperparameters 摺疊標題不再附說明文字

## 2026-09-14 接續訓練（Start from）

1. Model 下方多一列「Start from」：預設「published weights (fresh)」；同一模型有完成的 run 時列出「continue from <run> · N classes」，
   沒有就整列隱藏；Resuming 狀態下停用
2. 選一個 run：超參數的 epochs 立刻重算成約一半，名稱的滑鼠提示寫「continuing from an earlier run's weights…」
3. 新增一個類別並標幾張後按 Train：run 正常完成，Hyperparameters 記錄 init_from；模型的類別頭已依新類別數調整（rfdetr 載入時擴增）
4. Annotate 的 Select 設定列「Training」Continue / Fresh 決定迴圈每回合是否接續，Train 步驛徽章顯示「continues <run>」
