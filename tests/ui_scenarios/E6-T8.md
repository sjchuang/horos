# E6-T8 — 錯誤分析 UI(Evaluate 頁右欄「Error analysis」面板)

Evaluate 頁只有保留集指標與錯誤分析;上傳自己的照片試模型在 Lab 頁(燒杯 icon)。

## 啟動

```
horos ui <project>          # 專案需至少有一個 completed 的訓練 run
瀏覽器開 http://localhost:5000/evaluate
```

面板讀取的是評估時保存的原始偵測(`runs/<id>/eval/<split>.detections.json`)。
在本版本之前做過的評估沒有這個檔,面板會顯示「run an evaluation first」,
重新按一次「Run evaluation」即可。

本文件同時涵蓋 E6-T10「建議 conf threshold」(面板最上方的建議卡)。

## 測試步驟

### A. 進入點

1. 選一個 completed run,選 Split(test / valid),按「Run evaluation」等它完成
2. 右欄「Error analysis」面板從提示文字切換為完整內容;
   切換到沒有評估過的 split 時面板回到提示文字

### B. 總覽卡與混淆矩陣(E6-S5)

3. 四張卡:correct(藍)、missed(橘)、false positives(紅)、wrong class(紫)。
   對照檢查:correct + missed + wrong class = 該 split 的 GT 框總數
   (左欄報告底部的「N ground-truth boxes」)
3a. 「Per class」與「Confusion matrix」是兩個分頁,一次只顯示一個、各自佔滿整個面板寬度
   (兩者並排時矩陣要橫向捲、表格右邊被切掉,所以拆開)。預設停在 Per class,
   選擇記在瀏覽器裡,重新整理仍是上次那個
3b. 分頁列右側有一行說明,跟著當下的分頁換:在 Confusion matrix 是
   「rows: ground truth · columns: predicted」,在 Per class 是
   「N box(es) found but labeled as another class」
3c. 「Most confused pairs」跟著混淆矩陣走(同一個分頁),因為它就是矩陣非對角格的排序結果
4. 混淆矩陣(切到該分頁):列是 ground truth、欄是 predicted,最後一列/欄是 background(顯示為「—」)
   - 對角線格子綠色外框,數值越大底色越深
   - 最後一欄(GT → background)= 漏檢,橘色底
   - 最後一列(background → pred)= 誤報,紅色底
   - 其餘非對角格 = 類別混淆,紫色底;滑鼠停留顯示「N forklift predicted as pallet」
5. Per class 表(切到該分頁):recall、precision、missed、false、confused,
   非零的錯誤數以對應顏色標示;整個面板寬度,類別多也不會被切掉
6. Most confused pairs(在 Confusion matrix 分頁下方):依次數排序,
   格式「N  pallet → predicted as forklift」;
   沒有混淆時顯示「none — every matched box has the right class」

### B2. 建議 conf threshold(E6-T10)

6a. 面板最上方是建議卡:左邊藍色大字是建議門檻(兩位小數),右邊一句話說明。
   文字格式如「F1 peaks at 0.842, and anything from 0.34 to 0.46 scores as well.
   At 0.40 the run keeps 91% precision and 84% recall; the 0.50 default scores 0.780」;
   0.50 本來就落在最佳區間時,句尾改成「nothing needs changing」
6b. 卡片下方是掃描曲線:藍粗線 F-score、灰細線 precision、灰虛線 recall;
   淺藍色帶是「跟最高分一樣好」的區間;藍色直線是建議值,白色虛線是滑桿現在的位置
6c. 拉動滑桿時白色虛線**立刻**跟著移動(不必等重算),可直接看出自己選的點
   在曲線上的位置
6d. 按「Use this threshold」:滑桿跳到建議值,右邊數字同步,下面的矩陣與最差影像重算
6e. 右上三選一(Balanced / Fewer misses / Fewer false alarms,即 F1 / F2 / F0.5):
   換選項後建議值與曲線重算;「Fewer misses」通常給出較低的門檻,
   「Fewer false alarms」較高
6f. 卡片底部是每類別的建議值膠囊(如「forklift 0.42」);GT 框少於 10 個的類別
   以虛線外框＋淡化顯示,滑鼠停留說明「too few boxes for this number to mean much」
6g. 選 test split 時,建議卡下方多一行提醒:test 上調門檻就不再是未動過的保留集,
   valid 比較適合調
6h. 模型在該 split 什麼都沒抓對時,卡片左側轉為黃色,顯示 0.50 並說明無法建議
6i. 切換 IoU 0.50 / 0.75 時建議卡一起重算

### C. 門檻即時調整(E6-S3)

7. 拉動「Confidence ≥」滑桿(0.05–0.95):放手約 0.25 秒後所有數字、矩陣、
   最差影像**同步更新**,期間右側顯示「computing…」;沒有重跑推論(秒內完成)
8. 門檻拉高:false positives 減少、missed 增加;拉低則反之
9. 切換「IoU ≥」0.50 / 0.75:配對變嚴,correct 通常下降、missed 與 false 上升

### D. 最差影像(E6-S6)

10. 「Worst images — k of N images have errors」下方是縮圖網格,
    每張縮圖就是伺服器端畫好的疊圖 PNG,左下角徽章:橘=漏檢數、紅=誤報數、紫=錯類數
11. 排序:錯誤數多的在前;同錯誤數時漏檢面積大的在前
12. 圖例對照疊圖顏色:綠細框=被配對到的 GT、藍=正確、紅=誤報、橘虛線=漏檢、
    紫=錯類(標籤格式「pred 0.82 (gt: pallet)」)
13. 點縮圖開啟全螢幕檢視器:
    - 標題是檔名,右側「k/N」,底部顯示「a missed · b false · c wrong class · d correct」
    - ←/→ 或按鈕在最差影像間切換;Esc、叉叉,或點擊照片以外的暗色區域都可關閉
    - 檢視器**沒有** Confidence 滑桿(疊圖已按面板門檻在伺服器端畫好)
14. Lab 頁 Predictions 圖庫的檢視器行為不變(滑桿顯示、前端即時過濾)
15. 門檻調到讓所有錯誤消失時,網格被「No errors at this threshold」取代

### E. 判斷「模型問題 vs 標註問題」的實際用法

16. 開最差影像:橘虛線框裡若明顯有物件 → 模型漏檢;若框裡沒東西 → 標註錯誤。
    紅框裡若有真實物件 → 標註漏標,可回 Annotate 頁補框

### H. 匯出圖表(E6-T14)

28. 分頁列右側有「Export chart」與 PNG / PDF 下拉:按下去產生**一張**圖,
    左邊是混淆矩陣、右邊是每類別表格,直接下載
29. 圖用的是**當下**的 Confidence 與 IoU 滑桿值,以及當下的 split;
    調完滑桿再按,圖就是你螢幕上看到的那份分析
30. 圖上的內容:
    - 標題列:split、run id、模型、confidence / IoU、影像數、mAP@50、用哪份標記、
      右側是四個總數(correct / missed / false / wrong class)與建議門檻
    - 混淆矩陣:單一藍色深淺代表**該格佔該列的比例**(不是四種顏色),
      綠框標出對角線=正確;每格都印出實際數字,不必靠顏色讀數
    - 每類別表格:依框數由多到少,含 AP@50、recall、precision、missed、false、wrong class;
      recall 與 precision 後面有淡藍長條可快速掃視
    - 頁尾:最常混淆的一對、horos 版本與產生時間
31. 類別超過 26 個時,表格只列框數最多的 26 個並在頁尾註明「+ N more class(es) not shown」
32. 該 split 還沒評估過就按,狀態列顯示「run an evaluation first」

### G. 用哪一份標記評估(E6-T13)

22. 「Run evaluation」左邊是兩選一:**Current labels**(預設)/ Run snapshot
23. 預設「Current labels」:評估拿專案**現在**的標記當 ground truth。
    在 Annotate 頁改完 test 集的標記後,回來直接按「Run evaluation」,新數字立刻反映修正,
    不必重新訓練
24. 報告下方那行會寫「scored against the project's labels as they are now」,
    再下面列出這次的組成說明,例如:
    - 「N photo(s) labeled into this set since the run was trained.」訓練後才標好的照片也一起評
    - 「N photo(s) held back: the run trained on them…」split 被 Reshuffle 過時,
      模型訓練過的照片會被排除,不會拿自己的訓練資料充當保留集分數
25. 切到「Run snapshot」再評估一次:數字回到 run 訓練當下那份標記,
    說明行改成「scored against this run's own snapshot」——用來重現舊數字
26. 兩種模式的混淆矩陣、最差影像、建議門檻都跟著該次評估的 ground truth 走:
    評估完之後再去改標記,分析結果不會偷偷跟著變(要重新評估才會)
27. 保留集裡沒有任何模型沒訓練過的已標照片時,按下去會直接報錯說沒有東西可評,
    不會白跑一次推論

### F. 直接跳去改標記(E6-T11)

17. 縮圖右上角在滑鼠移上去時出現鉛筆圖示,點它**在新分頁**開 `/annotate#<image_id>`,
    直接進到該張照片的編輯畫面;點縮圖本身仍然是開疊圖檢視器(兩者不互相干擾)
18. 全螢幕檢視器有兩個入口,都在新分頁開該張照片:
    - 左上角的檔名本身就是連結(滑鼠移上去變藍並加底線,後面有鉛筆圖示)
    - 底部的「Fix labels」按鈕
19. 到達 Annotate 頁後:**直接就是編輯器**,不會先看到縮圖網格再跳頁。
    這張照片一定已經有標記,不在預設的「To do」佇列裡,所以頁面直接改用「By name」佇列;
    佇列在背後載入,載完後頂欄才補上「第幾/共幾張」與上一張／下一張
20. 改完標記回到 Evaluate 分頁,按一次「Run evaluation」(預設 Current labels):
    新數字就反映剛才的修正,不必重新訓練(見 §G)
21. 照片已從專案刪除時,Annotate 頁顯示「Image N is no longer in this project」

## 預期結果

不需離開 Evaluate 頁就能看出:哪些類最常被漏、哪些類最常被誤報、
哪兩類最常互相混淆;拉門檻立即看到取捨;最差影像一眼分辨模型錯或標註錯

### 分割模型的 overlay（E6-T6，2026-09-14）
1. 用 RF-DETR-Seg 的 run 評估後，Worst images 的縮圖與全螢幕檢視器畫的是 **mask**：
   預測以類別色多邊形外框＋半透明填色呈現，漏偵測（fn）畫 ground truth 的多邊形；
   純偵測 run 仍是矩形
2. 2026-09-14 之前做的評估沒有存多邊形：按一次「Evaluate」重跑即可

## 已知限制

- 混淆矩陣類別很多(>15)時仍需要橫向捲動,但已是整個面板寬度;尚無合併/摺疊
- 最差影像最多顯示 24 張;完整清單走 `horos analyze --worst N` 或
  `GET .../eval/<split>/worst?top=N`
- 疊圖是每次請求即時渲染;大型 split 反覆拉滑桿時縮圖會重新載入
- PR 曲線(pr_curve_50)仍未圖形化
- 建議門檻的網格是 0.01(0.05–0.95),不會建議比 0.05 更低或比 0.95 更高的值
- 建議是從該 split 保存的偵測算的:換了 split 就是換一組數字,兩者不必相同
- 建議值不會自動寫進推論服務或匯出設定;要沿用得自己在 Lab / serve 設定
- 「Fix labels」改的是專案現在的標記,不會回頭改 run 的資料快照;
  要讓數字反映修正,回 Evaluate 頁重跑一次評估即可(預設就是用現在的標記)
- 已經評估過的結果不會自動跟著標記更新:報告與分析都綁在該次評估用的 ground truth 上
- 匯出圖表只有 PNG 與 PDF(直接從 matplotlib 出圖);要表格資料請用 `horos analyze` 的 JSON修正
