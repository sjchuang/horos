# E1-T10 — WebUI 上傳與摘要頁

## 怎麼啟動

```bash
horos init ./demo_project
horos ui ./demo_project
# 瀏覽器開 http://localhost:5000
```

## 測試步驟

1. 準備一包資料集 zip：COCO（內含 `_annotations.coco.json`，flat 或 train/valid/test 子目錄皆可）或 YOLO（內含 `data.yaml`）
2. 開啟首頁，把 zip 拖進虛線框（或點擊選檔）
3. 上傳中虛線框下方應出現進度列，分兩段：
   - 傳輸中顯示 `Uploading 45% · 12.3 MB / 27.0 MB`，進度列跟著位元組數前進
   - 伺服器處理時依序顯示 `Extracting i/N` → `Reading annotations — <format>…` →
     `Checking for duplicates i/N` → `Copying images i/N` → `Saving annotations i/N`
     （最後一段 `Assigning splits`：有標記但來源未指定 split 的照片依穩定雜湊分到 train/valid/test），每段進度列歸零重跑
   - 處理期間虛線框呈半透明並拒絕第二個檔案（狀態列顯示 Still importing…）
4. 完成後應顯示解析摘要列：`Imported N images, M annotations, K classes (COCO/YOLO)`
5. 「Dataset」卡片應出現：影像數、標註數、類別數、train/valid/test 計數、以及「unlabeled · in no set」
   - 只有已標記的照片會被算進 train/valid/test；未標記照片不屬於任何 set，訓練快照與匹出的 split 目錄都不含它們
   - 「Splits · 70 / 10 / 20 %」摺疊列（預設收合，標題滑鼠提示說明規則）：展開後是比例步進器與 seed（來自專案設定）。「Assign splits」儲存比例並只把
     「有標記但還沒有 set」的照片依雜湊分配，已在 set 裡的不動；「Reshuffle…」需二次確認，警告會把先前模型
     訓練過的照片洗進 test；狀態列顯示 `a / b / c · n unlabeled in no set`
   - 在 Annotate 第一次存下確認標記的照片，回到這頁重新整理即可看到它已進入某個 set
6. 「Classes」表格應列出每個類別的實例數、涵蓋影像數與相對長條圖
7. 「Validation」區塊應顯示問題清單（乾淨資料集顯示綠色 No issues found；壞資料顯示 `[kind] message`，warning 黃色、error 紅色）
   - 訊息會寫出檔名，例如 `Annotation 1 on '20240121_140507.jpg' (image 1937): bbox … exceeds the image bounds …`
   - 影像相關的問題尾端有 `open annotation ↗`（或 `open image ↗`）連結；點下去開啟 Annotate 頁，
     直接進入該影像的編輯器，該標註被選取並以白色外框閃爍兩次
   - 有 `fixable` 問題時出現「Fix N issues automatically」按鈕。可自動修的兩種：框超出影像 ≤ 2 px（夾回邊界）、
     bbox 與自己的 polygon 範圍不一致但 polygon 覆蓋框寬高各 ≥ 50%（以 polygon 重算 bbox）。
     按下後狀態列顯示 `Repaired N box(es) (clamped into bounds / refitted to their polygons)`，清單重新整理
   - polygon 只覆蓋框的一小角（碎片）列為紅色 error `[polygon_bbox_mismatch] … is a fragment of the object …`，
     不提供自動修：到 Annotate 頁刪掉 polygon 後重跑 Boxes → polygons，或重畫
8. 頁尾「Models · licenses」摺疊列（預設收合）展開後的表格應列出 RF-DETR Nano/Small/Medium/Large 與 OWLv2，每列尾端有綠色 Apache-2.0 授權標示（E4-S2）
9. 上傳一個非 zip 檔或格式無法辨識的 zip，狀態列應顯示紅色 `Import failed: <明確原因>`，頁面不得卡死

## 預期結果

非工程使用者上傳一包 zip 即看到完整解析摘要（幾張圖、幾個類別、每類幾個實例），錯誤情境有明確訊息（E1-S3、E1-S4）

## 已知限制

- 「Reading annotations」階段沒有 i/N 計數（格式讀取器尚未回報進度），大型 LabelMe / COCO
  資料集在這段會停留數秒但進度文字仍在
- 匯入 job 不可取消（匯入是單一交易，半途中斷比做完更糟）
- 上傳大小上限 2 GB（更大的資料集請用 `horos import` 走檔案路徑）
- 頁面尚無標註入口與影像縮圖牆（E2 標註 UI 時加入）
- 模型表格目前只是資訊展示，選用模型的流程屬 E5 訓練 UI

## 附:Danger zone — 刪除所有資料(2026-09-12 新增)

1. 專案有影像或類別時,頁面最底部出現一行淡灰色的「Reset project…」摺疊列（沒有紅色標題,不展開看不到按鈕；
   2026-09-14 起取代原本的 Danger zone 面板）；展開後才有「also delete the classes」與紅框按鈕「Delete all photos and annotations…」
2. 按「Delete all images and annotations…」跳出對話框,要求輸入專案名稱;輸入錯誤或取消 → 顯示
   「name did not match — nothing deleted」,資料不變
3. 輸入正確 → 狀態列顯示「deleted N image(s), M annotation(s)」,Dataset summary 與 Validation 面板收起,
   類別保留(勾選「also delete the class list」則一併刪除並顯示 class 數)
4. 若其他標註者正開著某張圖(claim 未過期),該圖會被跳過並在狀態列說明
5. 訓練 run 與其資料快照不受影響;`horos clear --yes [--drop-classes]` 為 CLI 對應

## 附:Groups — 依相似度分群、整群 skip(E10-T20,2026-09-14 新增)

1. Dataset 頁 Classes 表下方、Splits 之後有折疊的「Groups · find and skip unfit photos in bulk」;展開
2. 「groups」步進器留空(auto ≈ √(照片數 ÷ 2),最多 24)或填數字,按 **Analyze**:
   若有照片尚未 embedding,狀態列先顯示「embedding N/M…」(跟 Select 步驟同一個 DINOv2 job),接著「grouping…」
3. 每組一張卡:最像中心的 6 張縮圖(點縮圖開到標註器該張)、「N photos · alike 0.93」、
   有標註時顯示「K labeled」、已 skip 顯示「S skipped」;組依大小排序
4. 按某組的 **Skip group**:該組全部照片 skip(與標註器的 Skip 同一機制:離開 pool、統計、快照與訓練);
   卡片變淡、按鈕變成 **Restore**;上方 Dataset 統計即時更新
4b. 組內有已標註照片時(縮圖綠框),按鈕分成兩個:**Skip unlabeled** 只 skip 未標註的、已標註的留下繼續訓練;
   **Skip all…** 連已標註的一起 skip,先 confirm 提醒標籤也會離開訓練
5. **Restore** 把該組 skip 的照片全部拉回
6. 改 groups 數再 Analyze:重新分群(相同 seed,相同輸入得到相同結果)

預期:一次把整批空景、放錯相機、重複畫面的照片排除;沒有 embedding 的照片不分組但會在狀態列計數
