# E10-T13 / T14 / T16 / T17 — Loop 頁面（四步驟殼；標註在 Annotate 頁進行）

## 怎麼啟動

```bash
horos init ./loop_demo            # 或用既有專案
# Dataset 頁匯入一批影像（zip 或 horos import <dir>），並先建立類別（例如 box）
horos ui ./loop_demo
# 瀏覽器開 http://localhost:5000/loop   （2026-09-14 起 loop 又是獨立一頁；/annotate 是純標註器）
```

## 測試步驟

（2026-09-14 起 Loop 頁**不再內嵌畫布**：Label 階段的進度列以藍色 **Annotate** 按鈕開 `/annotate?round=<n>[&annotator=]`，
落在第一張未標的照片；/annotate 首頁本身在有 labeling 輪時也預設顯示該輪的 to-do；Loop 頁每 5 秒輪詢進度）

### A. Select（零標記冷啟動）

1. 進入 `/loop`：頂端四步只有 Select 亮起；五個數字卡：to label / labeled / skipped / rounds / model
2. 策略徽章顯示「Spread out」（停留看說明）；滑桿拉到 10，主按鈕同步變成「Pick 10 photos」
3. 按 `%` 切成百分比：滑桿上限 100，按鈕文字帶「· 10%」並換算成張數
4. 徽章下方三組選項會記在專案裡、每回合沿用：**Model**（Auto / Boxes / Segm，選 Boxes 或 Segm 後會多一個尺寸下拉）、
   **Pseudo labeling**（On / Off，關掉就不寫偽標記）、**Shapes**（Auto / Box / Polygon；Auto 在 Model 為 Segm 或標記多為多邊形時等同 Polygon，會用 SAM 把框型偽標記轉成多邊形）；
   **Training**（Continue / Fresh；Continue 是預設：每回合從同一模型最新完成的 run 接續訓練，權重保留、optimizer 重來、類別頭依目前類別
   重設大小所以可以新增類別，epochs 約減半；第一回合或沒有同模型的 run 時自動 fresh。Train 步驛徽章會顯示「continues <run>」或「fresh start」）、
   **Balance**（On / Off，預設 On：類別預算依標記數反比加權，標記很少、模型還提不出來的類別改以「與它少數照片相似」的方式補位，
   最多佔回合四分之一；挑出的照片理由會寫「class balance: looks like the N labeled photo(s) of rare class …」）、
   **Scan ×**（模型評分的未標記張數 = 本回合張數 × 這個倍數，例如 20 × 100 = 2000；池子更大時隨機抽樣；空白或 0 = 全部，大池子會很慢；預設 100，
   評分改為每 16 張一批送模型，進度訊息顯示「n of N photos · k detection(s)」）；
   每個設定名稱（Model / Pseudo labeling / Goal / Scan / Shapes）、張數滑桿與上方六張統計卡片滑鼠停留都有說明；
   切換立即儲存，Label 步驛的回合徽章會顯示目前的模型
5. 按「Pick N photos」：進度條依序走 embedding → pre-annotating（第一次會下載 DINOv2 與 OWLv2 權重）
   - 進度中重新整理頁面：仍停在 Select、進度條與 Cancel 接回同一個工作（`/api/v1/loop` 的 `job` 指出進行中的工作），不會再出現 Pick 按鈕
   - 若挑選途中伺服器重啟，頁面顯示「Round N was interrupted…」與「Start over」；按下關閉該回合，歷史不留空回合
6. 完成後自動切到 Label

### B. Label（進度列、Annotate 按鈕、略過、多人）

1. 標頭預設是一條細狀態列：回合徽章、橫向進度條與 `0/N`（N = 回合有效張數；略過不計入分母，補進計入）、回合徽章、
   未達門檻時的第一個原因、Train 按鈕、右側 ⌄ 展開鍵；展開後才看到 Model / Pseudo labeling / Shapes 設定、分派名字、
   All photos、Re-pick 與完整原因清單；展開狀態會記住
2. 按藍色 **Annotate**：開 /annotate 於本回合佇列，直接落在第一張待處理影像；「← Round overview」回到本回合網格，導覽列 Loop 圖示回本頁
   - 開圖時 Class 欄自動帶入上一次標記用的類別（只有一個類別時直接帶入該類別），Draw 一點即可標；
     打字、點類別膠囊或標完一個形狀都會更新這個記憶
3. 接受或修正偽標記（Pseudo labels 卡片 Accept / Reject）；回到 Loop 頁後進度條在 5 秒內更新
   - 同一類別重疊 IoU ≥ 0.5 的偽標記只留分數最高的一個（RF-DETR 本身沒有 NMS，年輕模型會對一個物件吐出多個 query）；
     不同類別疊在同一物件上仍會都留下，由標記者決定
   - 工具只有三個：**Draw ✦（1）** 點一下物件就出現 SAM 遮罩預覽、右鍵點不是的地方、Enter 或 Space 都是接受（沒有 Next）、Esc 清除（Clear 按鈕標了 Esc）；
     輸出形狀跟隨 Shapes 設定（Box / Polygon）。沒有手拉框或逐點畫多邊形的工具
   - **Edit ✎（2）**：點選形狀後拖曳移動、拖曳控制點；**點邊線會在該處新增控制點**，
     **把一個控制點拖到另一個點上會合併**（中間較短那一段的點一起消失），Ctrl+Z 可還原
   - **Prompt T（3）**：輸入類別文字由 OWLv2 在此圖產生偽標記
4. **略過**：按 `S` 或工具列「Skip」：面板列出相似照片縮圖（預設相似度 0.80，可拉滑桿即時重算），
   全部預設勾選；按「Skip N photos」→ 這幾張標記為 skipped，回合自動從池子補進同樣數量的新照片
   （Toast 顯示「Skipped N · M added」，8 秒內可 Undo 略過；補進的照片保留），佇列重新載入並跳到下一張待處理影像；
   補進的照片繼承被略過那張的分派，也帶有預標記，理由以「replacement for a skipped photo」開頭
5. 略過的照片：Select 卡的 skipped 數字增加、to label 減少、不會再被挑選、不進訓練與統計；
   它們離開本回合的佇列與進度環（All photos 的「Done」篩選以 ⊘ 顯示）
6. 多人：名字欄輸入 `ann, bob` 按分派圖示；點名字膠囊切換各人的佇列；重新整理仍記得自己
7. Train 按鈕未達門檻時反灰並列出原因；達門檻後亮起。「↺ Re-pick」關閉本回合回到 Select
7a. 沒有類別不足的問題時，Train 旁**不會**出現「Train without N classes」按鈕
   （不是空白膠囊，是整顆不存在）
7b. 若**只有**「class 'X' has n instance(s); needs at least 5」這類原因擋住（張數已夠），Train 旁多一顆
   「Train without N class(es)」：hover 列出被略過的類別；按下即以有足夠標籤的類別開訓
   （這些類別的標註與只含它們的照片不進快照，`TrainRunConfig.categories`），Train 步驟徽章顯示「· without X, Y」，
   round.json 的 `training.ignored_classes` 記錄；CLI `horos loop train --ignore-short-classes`
8. 「All photos」開啟全專案畫布（含頁首導覽），可瀏覽與編輯任何照片
8b. 版面：Label 列分三段「徽章 | 進度條＋原因提示 | Annotate / Train without / Train / ⌄」。
   原因文字過長時先被截成「…」（滑鼠停留看全文），進度條最少保留 120px；把視窗縮到
   約 900px 以下，按鈕整組換到第二行靠右，任何按鈕都不得超出卡片邊界或被壓扁

### C. Train

1. 按 Train：徽章「Round 1 · rfdetr-nano」，進度條隨 epoch 前進，loss 曲線逐 epoch 出現
2. 「■ Stop」可中止；最佳權重保留，回合回到 Label 並提示
3. 正常結束自動切到 Review

### D. Review

1. 最上方是「要不要再標」的建議卡（顏色跟隨結論）：Keep going / Gains are flattening / Goal reached /
   Worse than last round — check the new labels / Nothing left，附一句理由（指標、相對上一回合的變化、
   每 100 張標記帶來的增益、剩餘張數），以及該 run 的體檢發現；主按鈕跟著建議變（繼續 → Next round、達標或平緩 → Done）
2. 大字顯示驗證指標（優先 val mAP）與相對上一回合的 ▲/▼；四個數字：本回合標記數、labeled、to label、skipped
   - 設定列的 **Goal**（0–1 的 mAP，0 或空白 = 沒有目標）達到後建議直接輸出；但若最後一回合 train 的 mAP@50 高出 test
     超過 0.05，建議卡改為「Keep going — train is still well above test」，達標也不建議輸出，直到兩條曲線靠近
   - 圖下方註記哪些回合是在 test set 存在前訓練的（沒有 Test score 點）；圖例自動落在沒有資料點的角落
   - 下方「Learning curve」是經典學習曲線：橫軸 Training examples（該回合模型實際訓練的張數，不含 held-out），
     縱軸 Score（mAP@50，範圍自動貼合資料），紅線圓點 Training score、綠線圓點 Test score，圖內右上有圖例、
     兩線之間淡淡上色顯示泛化差距；valid 不畫在圖上；
     每次按 Train 前，新標記的照片會依穩定雜湊分桶：20% 進 test（模型永遠看不到）、10% 進 valid（trainer 選 checkpoint），
     其餘訓練；held-out 只增不減。訓練完成後在背景評估三個切分，評估中會顯示提示並自動更新
3. 表格：Round / Step / How / Picked / Labeled / Skipped / Metric / Δ
4. 「Next round」關閉回合回到 Select，徽章變「Model-guided」；「✓ Done」停留在總結；「Evaluate」跳到評估頁

### E. 從 API 驗證（無瀏覽器時）

```bash
curl -s localhost:5000/api/v1/loop | python -m json.tool
curl -s -X POST localhost:5000/api/v1/loop/rounds -H 'content-type: application/json' -d '{"count": 10}'
curl -s localhost:5000/api/v1/loop/rounds/1 | python -m json.tool          # 每張的 score 與 reason
curl -s "localhost:5000/api/v1/images/3/similar?threshold=0.9"             # 相似照片
curl -s -X POST localhost:5000/api/v1/images/skip -H 'content-type: application/json' -d '{"image_ids":[3],"note":"blurry"}'
curl -s -X POST localhost:5000/api/v1/images/restore -H 'content-type: application/json' -d '{"image_ids":[3]}'
```

## 預期結果

不讀說明文字，只跟著亮起的步驟與唯一的主按鈕，可從零標記走完一圈；不適合訓練的照片一鍵連同相似照片略過，
且略過後從挑選、統計與訓練中消失、可還原。

## 已知限制

- 畫布引擎仍在同一個 `canvas.html`；`/annotate?round=<n>` 是回合佇列、`/annotate` 是全專案（舊的 `?canvas=1`、`?embed=1` 仍可用，但 Loop 頁已不內嵌）；沒有拆成獨立 JS 檔
- 相似照片依賴 DINOv2 向量：第一回合挑選前尚無向量時，面板只能略過單張並說明原因
- 分派為 round robin，重新分派會覆蓋既有歸屬；Stop 之後需再按 Train 才續訓
- 本機沒有無頭瀏覽器，頁面以 curl 與 node --check 驗證，請實際點一遍
