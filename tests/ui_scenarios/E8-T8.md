# E8-T8 — 訓練 run 匯出（報表 + 模型）

## 怎麼啟動

```bash
horos ui ./demo_project          # 專案需有至少一個 completed 的訓練 run
# 瀏覽器開 http://localhost:5000/train
```

## 測試步驤

### A. 報表匯出

1. 在 Run history 點一個 completed 的 run。「Training run」面板底部出現「Export」區塊；
   未完成或失敗的 run 不顯示此區塊
2. Report 下拉選 `PNG · one 16:9 dashboard image`，按「Export report」
   - 狀態文字先顯示 `rendering…`，數秒後變成 `ready — download training_report.png`
   - 下載後開啟：一張 1920×1080 的圖，含標題列（模型、run id、狀態、epochs、影像數、類別、授權）、
     loss 曲線（train/val，best checkpoint 虛線）、Validation mAP 曲線、best checkpoint 分數表、
     每類訓練實例長條圖、關鍵超參數、結論摘要與前三條建議
3. 選 `PDF`，按 Export report：第 1 頁與 PNG 相同，第 2 頁超參數與理由表，第 3 頁 evaluation
   分 split / 分類別 AP 表（未評估時顯示提示），第 4 頁結論與建議
4. 選 `Excel`：工作簿有 Summary、Metrics（每 epoch 一列、每個 metric 一欄）、Hyperparameters、
   Classes、Evaluation、Verdict 六個工作表
5. 每次匯出後下方清單多一列，可直接點檔名下載；同格式重匯會覆蓋

### B. 模型匯出

6. Model 下拉選 `PyTorch weights`，按「Export model」
   - 進度列出現，phase 依序顯示 `loading checkpoint` → `writing weights bundle` →
     `verifying against the original weights` → `writing model card` → `bundling`
   - 完成後 `ready — download <run>_pytorch.zip`；zip 內有 weights.pt、class_names.txt、model_card.json
7. 選 `ONNX`，按 Export model
   - phase 顯示 `tracing and exporting onnx (this takes a while)`，可能數十秒
   - 完成後狀態列尾端顯示 `parity OK (N detections matched, max score diff 0.0012)`；zip 內有 inference_model.onnx（或
     `<variant>.onnx`）、class_names.txt、model_card.json
   - model_card.json 含 weights_license / code_license / license_url、classes、input（shape、mean、std）、
     outputs（dets、labels 說明）、dataset（影像數、split、fingerprint）、metrics、hyperparameters、parity、
     **threshold（建議的推論信心門檻，E8-T4）**

7a. **建議信心門檻**（先在 Evaluate 頁對 test 或 valid 跑過一次評估，再回來匯出）：
   - 匯出完成的狀態列除了下載連結與 parity，還多一段「run at confidence **0.39**」，
     滑鼠停留顯示完整理由（F1 尖峰、等效區間、與 0.50 預設的比較）
   - model_card.json 的 `threshold` 區塊：
     - `confidence`：建議值；`metric`：F1；`precision` / `recall` / `f_score`：該點的表現
     - `plateau`：分數與尖峰相差 1 % 以內的區間
     - `derived_from`：來自哪個 split、IoU、用哪份標記（current / snapshot）、評估時間、影像與框數
     - `per_class`：每個類別自己的建議值，`enough_data` 標出 GT 少於 10 框、數字不可靠的類別
     - `notes`：例如「這是 test split」的提醒
   - 優先取 **test**，沒有評估過才退而取 valid
   - 完全沒評估過就匯出:`confidence` 是 `null`,`note` 寫「run 'horos evaluate' … and export again」,
     狀態列顯示「no suggested confidence」——不會編一個數字出來
   - 模型什麼都沒抓對時同樣是 `null`,`note` 說明原因
8. 選 `TensorRT engine`：下拉下方的說明文字明示引擎綁定本機 GPU 架構與 TensorRT 版本，不可搬到別台機器
   - macOS：該選項停用並寫明 `TensorRT is not supported on macOS`（由 /api/v1/capabilities 驅動）
   - CUDA 機器但未安裝 tensorrt 套件：按下後狀態列顯示明確錯誤，指示執行 `horos install --tensorrt`
     （依驅動的 CUDA 主版本裝 tensorrt-cu12 / cu13，NVIDIA 授權，僅在使用者要求下安裝），不會退回 CPU
   - 安裝後重試：phase 顯示 `tracing and exporting tensorrt (this takes a while)`，完成後 zip 內有 .trt 引擎、
     class_names.txt、model_card.json，model card 的 portability 欄寫明引擎不可攜
9. 匯出進行中「Export model」按鈕停用；完成或失敗後恢復

### C. 錯誤路徑

10. 對一個 failed 的 run：Export 區塊不出現；直接 POST `/api/v1/train/runs/<id>/export/model`
    會得到 `only completed runs can be evaluated or used for inference` 錯誤

## 預期結果

一個 completed run 的完整訓練結果可以一鍵變成可直接貼進簡報的 16:9 圖、多頁 PDF 或 Excel；
模型可帶著 model card（授權、類別、指標、資料指紋、parity 結果）以 PyTorch / ONNX / TensorRT 匯出並下載

## 已知限制

- TFLite 未提供（tensorflow 依賴約 600 MB，rfdetr 標為實驗性）
- Parity 檢查只對 ONNX 執行；PyTorch 權重包是原權重的直接序列化，TensorRT 引擎無 CPU 參考可比對
- 報表的 Evaluation 頁需要先在 Evaluate 頁跑過該 run 的評估，否則只有提示文字
- 匯出 job 與 autolabel / evaluate 共用「一次一個背景 job」的限制

### D. TFLite（E8-T3，2026-09-12 新增）

10. Model 下拉多了 `TFLite (float32 + float16, via ONNX)`。沒裝工具鏈時按 Export model
    會得到明確錯誤「horos install --tflite」，不會靜默退回別的格式
11. 裝好後匯出：phase 依序 `tracing and exporting onnx` → `converting ONNX to TFLite with onnx2tf`
    → parity → model card → bundling；bundle 內有 `<model>_float32.tflite`、`<model>_float16.tflite`、
    `class_names.txt`、`model_card.json`，沒有 .onnx
12. model_card.json 的 `input.shape` 仍是 NCHW（與 ONNX 相同契約），`parity.method` 註明
    「TFLite interpreter (CPU)」且 `parity.status` 為 passed
